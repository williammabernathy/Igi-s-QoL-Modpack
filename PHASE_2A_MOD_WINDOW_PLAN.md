# Igi's QoL Modpack: Phase 2a, mod window and per-ship controls

## Context

Phase 1 shipped the plugin core (`src/IgiQoL`: feature registry, `SaveData`, `GameEvents`, dev harness) and eight single-patch features. Phase 2a adds the in-game surfaces the user asked for: a mod window (hotkey + HUD button) with Settings, ECHO, Operations and Notes tabs; a command strip on every HUD fleet row; a per-ship settings popup; and three behaviours behind those controls: the ECHO activity priority list, the player's own operation defaults, and a per-ship engagement distance. Item rules tab, ECHO cargo rules and Contacts are Phase 2b (decided: item rules will then move from `item-rules.json` into the save; nothing in this plan touches `TractorCaps`).

Plugin conventions are the Phase 1 code itself: `src/IgiQoL/Core/Feature.cs` (feature contract, `Fail`, patch guard), `Core/SaveData.cs`, `Core/GameEvents.cs`, `Core/DevFeature.cs` (harness), `Core/SelfCheckContext.cs`, `Features/FleetVitals/FleetVitals.cs` (the Bind/Refresh postfix pattern and the prefab-copy self-check to copy for the strip).    public sealed class ShipSettings {
       public RetargetMode? missileRetarget;      // null = use [MissileRetarget] Mode
       public bool? dronesOnArrival;              // null = use [DronesOnArrival] Default

       public float engagementDistance = 10f;     // used when engagement == Fixed
       public static readonly ShipSettings Default = new();
